# Stillmake release flow: adopting it

Reference for moving a Stillmake macOS app onto the shared flow: DMGs as GitHub releases on `Stillmake/releases`, history and in-app feed in `<slug>/` there, a cask in `Stillmake/homebrew-tap`, optionally a homepage built from `Stillmake/releases`. Each piece below is independent.

## Preconditions

All required; this guide assumes every one holds.

- A notarized DMG holding one `.app`, built by the project's own tooling.
- `Stillmake/releases` and `Stillmake/homebrew-tap` checked out next to the source repo as `../releases` and `../homebrew-tap`.
- `gh` signed in, with write access to `Stillmake/releases` and the homepage repo, if any.
- Git push access to `../releases` and `../homebrew-tap`.
- `node` and `rg` on `PATH`.

Code: `templates/release.sh`, `templates/RELEASE.md`, `templates/cask.rb`, `scripts/feed.mjs`, `../homebrew-tap/scripts/bump.sh`.

## The one hard rule

Nothing points at a DMG until it is published: not the feed, the cask, or the site. `release.sh` enforces it.

## Naming

slug = app name, lowercased. It names `<slug>/`, tags `<slug>-{version}-{build}`, and `Casks/<slug>.rb`.

## Pieces

**History.** `<slug>/changelog.json`, newest first: `{ "version", "build", "notes": [{ "title", "items" }] }`. Seed it from any existing history; otherwise the first release's entry starts it. `version.json` is generated by `feed.mjs`. Add a row to `README.md`.

**Release script.** `templates/release.sh` → `scripts/release.sh` and `templates/RELEASE.md` → `RELEASE.md`. Fill in `__SLUG__`, `__APP__` and `__SITE_REPO__` (empty if there is no site).

**Cask.** `templates/cask.rb` → `../homebrew-tap/Casks/<slug>.rb`. Its URL resolves only once the build is on `Stillmake/releases`, so let the first release's `cask` stage commit and push it. Remove `auto_updates true` if there is no in-app updater. Without a homepage, use `https://github.com/Stillmake/releases`.

**In-app updater** (if any). Read `https://raw.githubusercontent.com/Stillmake/releases/main/<slug>/version.json` and download each entry's `url` as-is. Entries without `url` predate this repo.

**Homepage** (if any). Build from `<slug>/` in `Stillmake/releases`: a sibling checkout locally, a second `actions/checkout` in CI. `deploy.yml` needs `workflow_dispatch`.

**Bridge** (only when shipped builds read a legacy update feed). They never see `Stillmake/releases`, so publish the first build whose updater reads the new feed on the legacy channel too, once, by hand.
